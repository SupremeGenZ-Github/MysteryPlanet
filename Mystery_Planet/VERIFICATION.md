# PostgreSQL + Mapillary edition verification — 30 October 2026

- Version 1.3.0: 32 JavaScript tests passed on Node.js 24.22.1 with database integration enabled. A normal `npm test` without `TEST_DATABASE_URL` passes 30 tests and skips the two database integration tests.
- PostgreSQL compatibility tests used the production `pg` driver over a local PostgreSQL wire connection to PGlite's PostgreSQL engine. They cover schema bootstrap, all clue levels, duplicate/concurrent answers across independent application pools, rollback, progress/rounds after application restart, database health failures, source-fixture imports, repeated imports, exact parents, Unicode aliases, full-text indexes, search pagination and database-stored coverage reports. PGlite multiplexes connections; this is not a native Render concurrency/load or TLS test.
- No connection to the user's live Render database was made. Native Render authentication, TLS/network policy, available capacity and production load require verification after the private `DATABASE_URL` is configured. No user database URL or password was supplied or embedded.
- PostgreSQL tables live in the `mystery_planet` schema. Startup uses an advisory transaction lock and additive `CREATE IF NOT EXISTS` statements. Database failures do not trigger an automatic SQLite fallback. `/healthz` checks database availability.
- The original SQLite importer/server/core tests also pass. SQLite remains optional for offline local development or legacy paid disk hosting. Existing SQLite records are not automatically copied to PostgreSQL.
- Mapillary tests cover missing-token handling, endpoint selection, panorama/photo filtering, area and border checks, six-search budget, authorization/rate-limit failures, repeated-image rejection, coordinates, dateline boxes and viewer attribution/movement options.
- `npm run build` prepares pinned MapillaryJS 4.1.2 distribution assets and third-party notices, then validates required project/deployment files.
- Frontend and backend remain HTML/CSS/JavaScript and Node.js. No Python, Docker, database admin GUI or manual schema setup is required to deploy the application.
- The default Render configuration uses an existing PostgreSQL database via `DATABASE_URL`; it creates no second database or paid disk. A free web service may sleep. Free Render PostgreSQL expires after 30 days and has 1 GB capacity, so it cannot provide indefinite free database retention or host the full gazetteer.
- PostgreSQL backup support uses an administrator's compatible `pg_dump` through the environment, with credentials excluded from argv/output. A live `pg_dump`/restore run against Render was not performed. Keep backups outside ephemeral hosting and verify recovery separately.
- Mapillary client settings and missing-token UI were browser-checked in the previous edition. No frontend layout was changed for PostgreSQL. Live account authorization, imagery availability and WebGL playback still require a real client token.
- No deployment, paid resource purchase or multi-million-row production import was performed. The full-geography report is the earlier audited source snapshot; the current JavaScript importer was tested on fixtures.
